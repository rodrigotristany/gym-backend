# Backend Scaffold — Design

Date: 2026-08-21

## Purpose

Stand up the initial FastAPI backend for the gym platform described in `CLIENT.md`. This pass delivers a working project skeleton with database connectivity, migrations, and a full authentication system for two account types (staff and end users). It deliberately excludes the exercise/routine/subroutine domain models — those are a follow-up feature built on top of this foundation.

## Stack

- Python >= 3.12
- FastAPI
- SQLAlchemy 2.0 (async, via `asyncpg`)
- PostgreSQL
- Alembic for migrations
- JWT (`pyjwt`) + `bcrypt` for auth
- `requirements.txt` for dependency management (no poetry/uv/pdm)
- pytest + pytest-asyncio + httpx for testing
- Docker Compose for local dev (app + postgres)

This follows the `backend-python` skill's conventions throughout.

## Data model

Two tables in this pass, reflecting the roles in `CLIENT.md` (Admin, Professor, User):

**`admin_users`** — staff accounts (dashboard access)
| column | type | notes |
|---|---|---|
| id | uuid | primary key |
| email | string(255) | unique, indexed |
| hashed_password | string(255) | bcrypt |
| role | enum {`admin`, `professor`} | default `professor` |
| enabled | boolean | default true |
| created_at / updated_at | timestamp | via `TimestampMixin` |

**`users`** — mobile-app end clients (the "User" role from CLIENT.md)
| column | type | notes |
|---|---|---|
| id | uuid | primary key |
| email | string(255) | unique, indexed |
| hashed_password | string(255) | bcrypt |
| enabled | boolean | default true |
| created_at / updated_at | timestamp | via `TimestampMixin` |

No role column on `users` — the table is exclusively the "User" role from CLIENT.md; Admin/Professor live in `admin_users`. Both tables get an initial Alembic migration (autogenerated + reviewed).

Out of scope for this pass: Exercise, Routine, Subroutine, Category, favorites, and any profile fields beyond auth essentials. These are follow-up work once this foundation lands.

## Auth

Full flow, mirrored for both account types, per the skill's standard pattern — no half-finished auth:

- **Admin** (`/admin/auth/*`): login, logout, OTP verify, password recovery
- **User** (`/auth/*`): login, logout, OTP verify, password recovery

Mechanism:
- JWT access token, short-lived (`ACCESS_TOKEN_EXPIRE_MINUTES`, default 30)
- Refresh token as a server-side session row in the DB (not just a signed token), `REFRESH_TOKEN_EXPIRE_DAYS` default 7
- OTP for verification flows, `OTP_EXPIRE_MINUTES` default 10
- No third-party OAuth providers — first-party only
- Passwords hashed with bcrypt; never logged or returned in any response
- `Depends()`-based injection for current-admin / current-user checks; DB calls live in `services/`, never directly in routers

## Docker / local dev

Handed off to the `local-dev-env` skill conventions:
- `docker-compose.yml` with two services: `app` (built from the `Dockerfile` below) and `postgres`
- `Dockerfile`: `python:3.12-slim`, installs `requirements.txt`, runs `uvicorn app.main:app --host 0.0.0.0 --port 8000`
- `.env` wires `DATABASE_URL` to the compose Postgres service; `.env.example` documents every key with a placeholder value (no real secrets committed)
- `docker compose up` should produce a working app + DB with no other manual setup

## Testing & run commands

- pytest + pytest-asyncio + httpx (`AsyncClient`) for tests
- A smoke test hitting the health-check endpoint
- Auth-flow tests for both `admin_auth` and `user_auth`: register/login, refresh, OTP verify, password recovery
- Run commands (documented in `docs/spec.md`):
  - `uvicorn app.main:app --reload` (or `docker compose up`)
  - `alembic upgrade head`
  - `pytest`

## Error handling

Standard `HTTPException` with clear `detail` strings, per the skill's convention. No custom global exception-handling framework in this pass — scope is skeleton-only; revisit if/when business logic (routines/exercises) introduces more complex failure modes.

## Explicitly out of scope

- Exercise / Routine / Subroutine / Category models and endpoints
- User profile fields beyond auth (favorites, etc.)
- Frontend dashboard, mobile app
- CI/CD pipeline
- Production deployment configuration beyond the `prod` env setting placeholder
